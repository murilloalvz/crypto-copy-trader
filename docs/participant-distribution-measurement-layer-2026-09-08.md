# Participant Distribution Measurement Layer — 2026-09-08

Status: **PREPARATORY / SCORE-FREE / NO ECONOMIC CLAIM**  
Mode: **PAPER / RESEARCH / READ ONLY**  
Branch: `feat/participant-distribution-research`

## Purpose

This layer prepares causal measurement of how observed BUY activity is distributed across wallet addresses inside an already-detected market opportunity.

It does **not**:
- change the Solana detector;
- change v68 acquisition, pacing, bins, direction, horizon, gates, or feature;
- create a new economic experiment;
- assign bullish/bearish meaning;
- define thresholds;
- create a combined score;
- claim that distinct addresses are independent traders;
- claim that concentration proves manipulation;
- claim that repeated activity proves wash trading.

The current v68 prospective `flow60_buy_share_pct` holdout remains the active economic gate.

## Scientific question reserved for a future experiment

A possible future question is:

> Among episodes already admitted by the frozen market-first detector, does the causal distribution of BUY activity across observed wallet addresses contain incremental information about forward outcomes?

This question is **not tested by this implementation**.

## Why this is not just v55 raw breadth again

v55 already included raw fields such as:
- `flow10_unique_buy_wallet_count`;
- `flow30_unique_buy_wallet_count`;
- `flow60_unique_buy_wallet_count`;
- `flow30_repeated_wallet_event_share_pct`;
- `flow60_repeated_wallet_event_share_pct`.

Those candidates are part of the burned v55 discovery family and cannot simply be promoted after v68.

This measurement layer adds distribution-shape primitives that can distinguish episodes with the same event count and the same number of known buyer addresses but different dominance structure.

Example:

- four BUY events from four wallets: `1,1,1,1`;
- four BUY events from two wallets: `3,1`.

The second case has greater event concentration even though both may still show multiple buyer addresses.

## Causal inclusion rule

For a market trade observation to enter a measurement window it must satisfy both:

1. market-time membership:
   `as_of - window_seconds < chain_time <= as_of`
2. knowledge-time membership:
   `observed_at <= as_of`

Therefore an old historical event discovered after `as_of` cannot be retrospectively inserted into the feature.

This preserves the existing dual-clock causal boundary used by the market-first research stack.

## Raw outputs

`src/participant_distribution_research.py` currently exposes:

### Counts / coverage
- `market_event_count`
- `buy_event_count`
- `sell_event_count`
- `known_market_wallet_event_count`
- `known_unique_market_wallet_count`
- `market_wallet_identity_coverage_pct`
- `known_buy_wallet_event_count`
- `known_unique_buy_wallet_count`
- `buyer_wallet_identity_coverage_pct`

### Buyer distribution shape
Only when every BUY event in the window has wallet identity:

- `buyer_breadth_ratio`
  - `unique buyer addresses / BUY events`
- `buyer_repeated_event_share_pct`
  - repeated BUY-event share implied by the same address appearing more than once
- `top1_buyer_event_share_pct`
  - fraction of BUY events generated by the most active buyer address
- `top3_buyer_event_share_pct`
  - fraction of BUY events generated by the three most active buyer addresses
- `participant_buy_event_hhi`
  - Herfindahl-Hirschman index over buyer event shares, in `[0, 1]`

These are event-distribution measures, not capital/notional concentration measures.

## Missingness policy

If BUY wallet identity coverage is partial, structural buyer metrics are deliberately `None`.

The layer does not calculate HHI/top-K/breadth on only the known-wallet subset and present that value as complete. Doing so could bias concentration downward or upward depending on which identities are missing.

Explicit flags include:
- `partial_market_wallet_identity_coverage`
- `partial_buyer_wallet_identity_coverage`
- `buyer_structural_metrics_unavailable_due_to_partial_identity`
- `no_market_events_in_window`
- `no_buy_events_in_window`

## Epistemic boundaries

Every result carries cautions that preserve these distinctions:

- distinct wallet addresses are **not proven independent traders**;
- participant concentration is **not manipulation evidence**;
- participant repetition is **not wash-trading evidence**.

Funding-linked dependence, common-funder graphs, ownership inference, and participant clustering remain separate research problems.

## Candidate multiplicity warning

The measurement layer intentionally exposes descriptive primitives, but a future economic discovery must not treat algebraically dependent transforms as separate independent hypotheses.

For example:

`buyer_breadth_ratio = unique_buyers / buy_events`

and

`buyer_repeated_event_share_pct = 100 * (1 - buyer_breadth_ratio)`

when buyer identity is complete.

They are two representations of the same underlying dimension and should not both inflate a future candidate set.

Likewise `top1`, `top3`, and HHI are correlated concentration summaries. A future discovery protocol must predeclare a small closed candidate set and a selection rule before outcomes are reviewed.

## What this implementation proves

If tests pass, it establishes only that the project can deterministically measure participant-event distribution under explicit causal and missingness rules.

It does **not** establish:
- that broad participation predicts positive returns;
- that concentration predicts negative returns;
- that any HHI/top-K threshold is useful;
- that participant structure adds information beyond `flow60_buy_share_pct`;
- that the route-only edge is executable;
- that a combined strategy is profitable.
